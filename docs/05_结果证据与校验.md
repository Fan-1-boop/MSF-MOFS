# 参考记录、重跑结果与历史来源如何区分

- **`results/reference/`**：论文已存档的参考搜索记录（来源于历史项目），全部使用相对路径。
- **`results/reproduced/`**：运行脚本产生的新记录，包括本机实验、统计和日志。只有明确运行过的实验才能称为独立复现。
- **`evidence/`**：与 `results/reference/` 不同来源的原始证据、论文协议、V6/V8 原版来源核验。
- **`provenance/RESULTS_REFERENCE_MANIFEST.json`**：每个正式参考文件的相对路径、字节数和 SHA-256。
- **`provenance/SHA256SUMS.txt`**：交付包文件哈希，通过 `python run.py integrity` 核验。

截图中类似 `/mnt/data/MSF_MOFS_Repro_Project_v2/...` 是早期合并机器路径，对 Windows 不具备定位意义。已从结果主目录移除携带旧绝对路径的 merge manifest，正式来源清单仅保存**项目相对路径**。旧 V8 冻结来源哈希清单中仍可含原环境文件名；那些只是原始文字证据，不会被作为实际输入读取。

**数据使用规则**：先运行 `paper status` 检查归档数量；想核实当前机器重跑是否覆盖论文，则读取 `results/reproduced/paper/` 中的新 CSV，再运行 `paper stats --input ...`；不要把两个集合合并后称为全部独立复现。
