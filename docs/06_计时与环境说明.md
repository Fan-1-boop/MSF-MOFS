# 07 特征提取耗时及环境差异

## 三种证据必须分开

| 证据 | 582维中位耗时 | 140维中位耗时 | 下降幅度 |
|---|---:|---:|---:|
| 历史 V6 原论文环境 | 556.11 μs/frame | 223.58 μs/frame | 59.80% |
| 历史脚本在此前本机重跑 | 1026.73 μs/frame | 380.36 μs/frame | 62.95% |
| 此前新增保存逐次耗时的独立测试 | 939.33 μs/frame | 355.78 μs/frame | 62.12% |

第三组计时的4000条原始数据位于 `results/reference/deployment/timings_raw.csv`，对应 `v6_original_140_summary.json`。历史 V6 原脚本 `src/satellite/msf-training/benchmark_v6_runtime.js` 保持不变，仅供来源和方法对照；不能让其直接覆盖原版历史结果。

## 本机独立重新计时
```bash
python run.py benchmark --repeats 2000 --warmup 100
```

新计时使用相同 Node.js 进程、相同冻结模型、同一64点遥测输入，分别计算582维及按需140维，保存逐次微秒耗时、均值、中位数、p95和p99。推荐至少多次运行，对比系统负载和预热条件。运行输出写入 `results/reproduced/satellite/deployment_benchmark/`，重复运行会覆盖的是自己的 `_local` 文件，不会触碰历史证据。

计算公式：`中位时间降幅 = 1 - median(140) / median(582)`；`加速倍数 = median(582) / median(140)`。

## 为什么不一定是59.8%？
Node.js版本、CPU架构、CPU频率与线程争用、JIT预热、垃圾回收、性能计数器粒度、内存布局、提取历史长度都会影响绝对微秒数和两组之间的比值。把本机结果人为调到59.8%不属于科学复现；应该如实保留原始记录及测试环境。**正确性由特征值的一致性测试证明，性能由独立统计描述，而非历史百分比相等来证明。**
